Documentation Technique & Reconstitution — Projet NetFortress

Jalon : Semaine 1-2 | Objet : Déploiement L2/L3, Segmentation VLAN 802.1Q et Politiques de Filtrage Pare-feu

1. Ressources Téléchargées, Justification & Sources

Logiciel / Image Source Rôle au sein du projet
UTM Virtual Machines mac.getutm.app Hyperviseur bare-metal émulant les cartes VirtIO avec accélération native Apple Silicon (ARM64).
OPNsense (aarch64) opnsense.org/download Système de pare-feu/routeur sous FreeBSD assurant le trunk 802.1Q, le routage inter-VLAN et le filtrage Packet Filter.

2. Dimensionnement des Machines Virtuelles dans UTM

  • VM OPNsense : ARM64 | 1 Go RAM | Disque dur virtuel de 2,9 Go.
    • vtnet0 (Interface 1) : Réseau partagé (NAT UTM) — émulation du lien WAN relié à Internet.
    • vtnet1 (Interface 2) : Réseau isolé de l'hôte (Host-Only) — support physique du Trunk 802.1Q.
  • VM Alpine Linux : ARM64 | 512 Mo RAM | Live RAM (sans stockage persistant).
    • eth0 (Interface 1) : Rattachée au réseau isolé de l'hôte d'UTM pour s'interconnecter à vtnet1.

4. Procédure Chronologique & Commandes Exécutées

Phase A : Configuration d'OPNsense (Menu Console & Shell)

Au démarrage d'OPNsense, le terminal présente la console interactive d'administration :

1. Assignation des interfaces et création des VLANs (Option 1) :

  • Saisie de 1 dans le menu principal (Assign interfaces).
  • Invitation Do you want to configure VLANs now? : saisie de y.
  • Création du VLAN 10 : interface parente vtnet1, tag 10. L'interface logique est nommée vtnet1_vlan10.
  • Création du VLAN 30 : interface parente vtnet1, tag 30. L'interface logique est nommée vtnet1_vlan30.
  • Affectation des rôles : WAN affecté à vtnet0, LAN affecté à vtnet1_vlan10, OPT1 affecté à vtnet1_vlan30.

2. Définition des adresses IP (Option 2) :

  • Saisie de 2 dans le menu principal (Set interface IP address).
  • Sélection de l'interface WAN (vtnet0) : activation du client IPv4 via DHCP (y).
  • Sélection de l'interface LAN (vtnet1_vlan10) : DHCP désactivé (n), adresse IPv4 positionnée à 10.10.10.1, masque CIDR fixé à 24, pas de passerelle amont (Entrée).
  • Sélection de l'interface OPT1 (vtnet1_vlan30) : configuration de l'IP 10.30.30.1 avec un masque de 24.

3. Équivalent en commandes pures (Option 8 - Shell) :

# Configuration automatique du WAN
dhclient vtnet0

# Création et adressage des passerelles VLAN sur vtnet1
ifconfig vtnet1_vlan10 create vlandev vtnet1 vlan 10
ifconfig vtnet1_vlan10 inet 10.10.10.1/24 up

ifconfig vtnet1_vlan30 create vlandev vtnet1 vlan 30
ifconfig vtnet1_vlan30 inet 10.30.30.1/24 up

Phase B : Configuration Réseau d'Alpine Linux (Sonde de test)

Connexion en root sur le système client :

# Création et montage de la patte balisée 802.1Q
ip link add link eth0 name eth0.10 type vlan id 10
ip link set dev eth0.10 up

# Adressage IP et déclaration de la passerelle par défaut
ip addr add 10.10.10.50/24 dev eth0.10
ip route add default via 10.10.10.1 dev eth0.10

# Inscription dans la configuration réseau locale
cat << 'EOF' > /etc/network/interfaces
auto lo
iface lo inet loopback

auto eth0
iface eth0 inet manual

auto eth0.10
iface eth0.10 inet static
    address 10.10.10.50
    netmask 255.255.255.0
    gateway 10.10.10.1
EOF

Phase C : Application des Politiques de Sécurité & Persistance (OPNsense)

Dans l'option 8 (Shell) d'OPNsense, écriture du script d'amorce dans le répertoire des hooks système pour pérenniser les règles après reboot :

echo 'echo "block in log quick on vtnet1_vlan10 to 10.30.30.1/24" >> /tmp/rules.debug' > /usr/local/etc/rc.syshook.d/start/99-netfortress.sh
echo 'echo "pass in quick on vtnet1_vlan10" >> /tmp/rules.debug' >> /usr/local/etc/rc.syshook.d/start/99-netfortress.sh
echo 'pfctl -f /tmp/rules.debug' >> /usr/local/etc/rc.syshook.d/start/99-netfortress.sh
chmod +x /usr/local/etc/rc.syshook.d/start/99-netfortress.sh

# Application immédiate dans le noyau Packet Filter
pfctl -f /tmp/rules.debug

Contrôle de l'intégrité du fichier généré :

cat /usr/local/etc/rc.syshook.d/start/99-netfortress.sh
Résultat obtenu :
echo "block in log quick on vtnet1_vlan10 to 10.30.30.1/24" >> /tmp/rules.debug
echo "pass in quick on vtnet1_vlan10" >> /tmp/rules.debug
pfctl -f /tmp/rules.debug

5. Campagne de Validation & Résultats Constateurs

1. Test d'accès nominal au segment local (Alpine Linux)

ping -c 3 10.10.10.1
Résultat : 3 packets transmitted, 3 packets received, 0% packet loss.
Conclusion : La liaison L2 802.1Q et la communication L3 avec la passerelle locale sont opérationnelles.

2. Test de rupture de transit inter-VLAN (Alpine Linux)

ping -c 3 10.30.30.1
Résultat : 3 packets transmitted, 0 packets received, 100% packet loss.
Conclusion : L'isolement strict de la zone Base de données est effectif au niveau IP.

3. Test d'interdiction de connexion L4 MySQL (Alpine Linux)

nc -z -v -w 2 10.30.30.1 3306
Résultat : nc: 10.30.30.1 (10.30.30.1:3306): Operation timed out.
Conclusion : Le port TCP/3306 ne répond pas, attestant d'un rejet silencieux conforme à la politique de sécurité.

4. Preuve de rejet actif dans les journaux du pare-feu (OPNsense)

tcpdump -nettti pflog0 "dst 10.30.30.1"
Résultat capturé :
00:00:00.000000 rule 96/0(match): block in on vtnet1_vlan10: 10.10.10.50 > 10.30.30.1: ICMP echo request
00:00:01.004057 rule 96/0(match): block in on vtnet1_vlan10: 10.10.10.50 > 10.30.30.1: ICMP echo request
Conclusion : La destruction des paquets provient de la règle de sécurité 96 appliquée par le pare-feu.

6. Difficultés Rencontrées & Résolutions Techniques

  • Routage manquant sur Alpine : Message ping: sendto: Network unreachable lors du test vers 10.30.30.1. Résolu par l'adjonction de la route ip route add default via 10.10.10.1 dev eth0.10.
  • Syntaxe Netcat BusyBox : Blocage de la commande sans argument de délai. Résolu par la syntaxe explicite nc -z -v -w 2 <IP> <Port>.
  • Comportement du shell csh d'OPNsense : Erreurs Event not found (sur le caractère !) et -e: not found (sur echo -e). Résolu par des écritures séquentielles via echo '...' >> délimitées par des apostrophes.
