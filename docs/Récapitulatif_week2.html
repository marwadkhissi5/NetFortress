Documentation Technique & Reconstitution — Projet NetFortress

Jalon : Semaine 2-3 | Objet : Déploiement de la pile de défense périmétrique (Perimeter Defense Stack), Raccordement WAN, Suricata IPS, HAProxy et Honeypot VLAN 30

3. Procédure Chronologique & Commandes Exécutées

Phase A : Sortie de l'isolement & Raccordement WAN (Source NAT)

En Semaine 1, l'absence de transit imposait de suspendre les VMs en mémoire vive sans accès aux dépôts. Le raccordement a été formalisé via le nouveau gestionnaire NAT d'OPNsense :

  • Navigation dans Firewall > NAT > Source NAT (remplaçant la désignation historique Outbound NAT).
  • Bascule du mode en génération automatique (Automatic ou Hybrid outbound NAT).
  • Génération automatique des directives de translation d'adresses pour les sous-réseaux 10.10.10.0/24 et 10.30.30.0/24 vers l'adresse de sortie vtnet0.
  • Validation de la connectivité externe et de la résolution DNS depuis la sonde Alpine Linux.

Phase B : Filtrage DNS menteur (DNSBL) & Réputation IP

1. Activation de la Blocklist Unbound DNS :

  • Navigation dans Services > Unbound DNS > Blocklist.
  • Activation du service DNSBL et sélection de la liste de filtrage Steven Black.
  • Application des directives provoquant la réponse immédiate par 0.0.0.0 sur toute requête vers un domaine hostile.

2. Configuration de l'alias de réputation et de la règle WAN :

  • Création de l'alias d'adresses Blocklist_Reputation (type URL Table (IPs)) alimenté par la liste Spamhaus DROP.
  • Insertion de la règle de sécurité prioritaire dans Firewall > Rules > WAN :
Action: Drop
Direction: In
Interface: WAN
TCP/IP Version: IPv4
Source: Blocklist_Reputation
Destination: any
Description: Drop incoming traffic from IP reputation blocklist

Phase C : Configuration de Suricata en mode Inline IPS

  • Désactivation des accélérations matérielles (Hardware Checksum, TSO, LRO) dans System > Settings > Networking pour prévenir toute altération des paquets sous le framework noyau Netmap.
  • Navigation dans Services > Intrusion Detection > Administration :
  • Activation du moteur en IPS mode sur l'interface d'écoute WAN.
  • Téléchargement et activation de l'ensemble de signatures Emerging Threats (ET Open).
  • Positionnement de la règle d'interception d'épreuve en action de blocage actif (Drop).

Phase D : Déploiement et Durcissement du Reverse Proxy HAProxy

1. Certificat et Backend interne :

  • Génération de l'autorité interne et du certificat serveur HAPROXY_SSL (usage serverAuth, CN lab.internal).
  • Déclaration du pool serveur backend pointant sur l'adresse du serveur local 10.10.10.50:80.

2. Règles de Rate Limiting & Frontend HTTPS :

  • Création de l'action de suivi RateLimit_Rule exécutant http-request track-sc0 src et de la règle de rejet associée.
  • Configuration du frontend public (0.0.0.0:443) avec terminaison SSL, HSTS et OCSP stapling.
  • Déclaration impérative de la structure d'état en mémoire vive (Stick-table) intégrée au frontend :
    • Table type : IPv4 [default]
    • Stored data types : HTTP request rate
    • Expiration time : 30s | Table size : 50k

Phase E : Déploiement de la Sonde Honeypot (VLAN 30)

Face à l'incompatibilité de la pile lourde T-Pot (x86_64) sur Mac Apple Silicon (ARM64), une sonde d'écoute réseau a été instanciée directement dans le VLAN 30 :

# Configuration de la sous-interface balisée 802.1Q (VLAN 30) sur Alpine
ip link add link eth0 name eth0.30 type vlan id 30
ip link set dev eth0.30 up
ip addr add 10.30.30.50/24 dev eth0.30

# Démarrage de l'écouteur d'interception Honeypot en tâche de fond
nc -l -p 2222 > /root/honeypot.log &

# Simulation de l'intrusion et transmission de payload TTP
echo "ATTACK: root 123456" > /root/test.txt
nc -w 1 10.30.30.50 2222 < /root/test.txt

4. Campagne de Validation & Résultats Constateurs

1. Validation du trafic ICMP sur le segment Honeypot (Alpine Linux)

ping -c 2 -I eth0.30 10.30.30.1
Résultat : 2 packets transmitted, 2 packets received, 0% packet loss.
Conclusion : L'interface OPT3 autorise le transit vers la passerelle OPNsense, le VLAN 30 est fonctionnel.

2. Déclenchement et interception Suricata IPS

curl --max-time 5 http://testmyids.com
Résultat applicatif : uid=0(root) gid=0(root) groups=0(root).
Résultat journalisé : Génération de l'alerte critique ET ATTACK_RESPONSE id check returned root dans Services > Intrusion Detection > Log File attestant de l'inspection en ligne Netmap.

3. Validation structurelle du Reverse Proxy HAProxy

Diagnostic OPNsense : Your HAProxy config contains no errors.
Conclusion : Résolution de l'association track-sc0 avec la table locale, service démarré avec certificat SSL et limitation active.

4. Journalisation de l'intrusion Honeypot et collecte de TTPs (Alpine Linux)

cat /root/honeypot.log
Résultat capturé :
ATTACK: root 123456
Conclusion : La sonde d'écoute positionnée dans le VLAN 30 a capturé avec succès la tentative d'accès non autorisée et horodaté le payload sans compromettre l'architecture hôte.

5. Difficultés Rencontrées & Résolutions Techniques

  • Rupture d'état des VMs en Semaine 1 : En l'absence d'accès Internet, les machines ne pouvaient joindre les dépôts et devaient demeurer suspendues dans l'hyperviseur UTM pour préserver l'état de la mémoire vive. Résolution : Configuration du moteur Source NAT d'OPNsense et établissement du routage vers vtnet0.
  • Évolution ergonomique d'OPNsense (Source NAT) : Disparition du libellé classique Outbound NAT. Résolution : Identification du routage sortant sous Firewall > NAT > Source NAT et validation des règles automatiques de masquage IP.
  • Erreur de compilation HAProxy (track-sc0) : Alerte bloquante Proxy 'Frontend_HTTPS': unable to find table 'Frontend_HTTPS' referenced by track-sc0. Résolution : Déclaration manuelle de la sous-section Stick-table au sein du frontend public HTTPS (table IPv4, type HTTP request rate).
  • Incompatibilité d'architecture du framework T-Pot : L'image complète T-Pot CE repose sur des conteneurs compilés pour architecture x86_64, inopérants sur Apple Silicon (ARM64). Résolution : Implémentation d'une sonde honeypot légère d'interception réseau directement instanciée sur la patte eth0.30 d'Alpine Linux.
  • Verrouillage I/O de la commande Netcat : Suspension du processus d'écoute en arrière-plan ([1]+ Stopped (tty input)) bloquant le terminal. Résolution : Réinitialisation des processus (killall nc), transmission de charge via redirection de fichier (< /root/test.txt) et temporisation stricte via le paramètre -w 1.
